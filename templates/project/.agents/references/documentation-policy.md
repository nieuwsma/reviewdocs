# Shared documentation policy

Resolve authored source roots, report paths, artifact IDs, private state and producer commands from `reviewdocs.config.mjs`. Default paths in examples are not mandatory. A trusted `.mjs` configuration and presentation module execute code when loaded.

Preserve consumer-owned files, canonical finding IDs, prior dispositions and dated history. A tool upgrade or documentation refresh does not authorize a review, remediation, deployment, publication or release. Follow the user's task authorization; routine local verification within that task needs no separate approval.

Publish documentation pages and illustrations. Cite implementation, configuration and retained evidence as plain checkout-relative filenames. Do not copy or link source downloads, archives, raw evidence, credentials, private keys, customer data or live identifiers. Keep producer proof and fingerprints in private state; publish their interpretation in prose. Renderer runtime assets are generated separately from authored illustrations.

Classify source-read, mocked, integration, canary, deployment and manual proof separately. Inspect explicitly selected consumer commands and their resource isolation before executing evidence. Failed, partial, unavailable and stale proof cannot support a passing claim. Build, check, verify and doctor do not decide whether a product finding is fixed or a release is ready.

Reuse the selected product visual system. Inspect installed components and tokens before modifying presentation. When Foundation is selected, use the `reviewdocs/foundation` adapter and local compiled assets. Keep supplemental styles limited to prose, diagrams and print; fingerprint theme producer inputs and installed assets, and carry presentation into bundled help.
